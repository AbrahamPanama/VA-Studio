# Native artwork library format — version 1

Implementation status: archive, manifest, immutable package, editable catalog,
catalog-to-package encoding, local storage and detached native selection staging
have focused local development tests. The native view is under development.
This document is not a claim
that the library panel, SVG insertion, LightBurn conversion, atomic publication,
recovery or Windows qualification is complete. The product acceptance contract
remains section 27 of `NESTING_FEATURE_ROADMAP.md`.

## Container and identity

A `.valib` is a ZIP32 package, not a renamed `.lbart`. Detection uses the package
contents, not its filename extension. Entry names are case-sensitive portable
ASCII identifiers. The ZIP reader rejects case aliases, traversal, absolute
paths, reserved Windows names, symlinks, encryption, unsupported compression,
overlapping/unindexed payloads, conflicting headers and invalid checksums.
Stored and raw-DEFLATE entries are accepted; the current writer emits stored
entries. ZIP64 and multi-disk containers are not supported in version 1.

```text
library.json
assets/<asset-uuid>.svg
previews/<asset-uuid>.png    optional disposable cache
```

Every catalog asset requires its exact SVG entry. Orphan previews/assets and
other unknown archive payloads are rejected rather than silently discarded
during a future rewrite. Unknown optional JSON metadata is preserved instead.
Adding new payload types requires an explicit format compatibility decision.

`Package::open` indexes the archive and reads only `library.json`. It does not
inflate artwork or previews. `read_artwork(id)` checks both ZIP CRC and the
catalog SHA-256 before returning a fresh byte buffer; `verify_artworks` checks
all authoritative artwork one entry at a time. SHA-256 binds the payload to the
manifest but does not authenticate its author or establish safe SVG content.

Previews never substitute for artwork. Missing previews are valid; damaged
preview bytes are reported when read and can be regenerated by the future
preview service. The service must use a bounded decoder and a cache key that
includes artwork hash and renderer version. This layer neither decodes PNG nor
verifies that a supplied thumbnail depicts the current artwork.

## Manifest schema

UTF-8 JSON, a single root object, with these required fields:

| Field | Contract |
| --- | --- |
| `format` | Exactly `org.vacards.artwork-library` |
| `formatVersion` | Integer `1`; newer/unknown versions are refused, never rewritten |
| `id` | Library UUID in lowercase hexadecimal `8-4-4-4-12` spelling |
| `name` | Nonempty display name, at most 1,024 UTF-8 bytes |
| `revision` | Unsigned 64-bit integer; no fractional/exponential representation |
| `assets` | Ordered array of at most 10,000 asset objects; empty is valid |

Each asset has these required fields:

| Field | Contract |
| --- | --- |
| `id` | Same UUID spelling; unique within the collection |
| `name` | Display name, at most 1,024 UTF-8 bytes; not a filesystem path |
| `tags` | Array of at most 32 unique strings, each at most 128 UTF-8 bytes |
| `path` | Exactly `assets/<id>.svg` |
| `sha256` | 64 lowercase hexadecimal characters over the exact SVG bytes |
| `widthMm`, `heightMm` | Finite positive numbers, at most 1,000,000,000 millimeters |

Names and tags reject ASCII control characters, DEL, empty strings and strings
containing only ASCII spaces. UUID validation checks canonical shape, not UUID
version/variant bits. Optional root/asset members round-trip as JSON values and
must not collide with reserved fields. They cannot grant access to resources,
code execution, filesystem paths or a newer format version.

Dimensions in the manifest are metadata until the SVG import service verifies
them against `width`, `height` and `viewBox`; thumbnail DPI is not evidence.
Preserving bytes and dimensions here is not proof of visual fidelity, editable
text, internal-reference safety or successful document insertion.

## Strict JSON and budgets

Duplicate keys are rejected, including escaped aliases and nested optional
objects. Invalid UTF-8, invalid surrogate sequences, comments, trailing data,
NaN and Infinity are rejected. Default limits are:

| Resource | Limit |
| --- | --- |
| Compressed package | 512 MiB |
| One uncompressed entry | 32 MiB |
| Sum of declared uncompressed entries | 1 GiB |
| ZIP entries | 20,001 |
| Manifest bytes | 16 MiB, checked before inflation |
| JSON nesting | 16 levels |
| Object members / array elements | 256 / 10,000 |
| JSON key / string | 128 / 4,096 bytes |

Callers may lower archive/manifest limits. ZIP32 capacity and the manifest's
hard parser limits still apply. Cancellation is checked during indexing,
inflation and catalog traversal; SHA-256 processes at most 64 KiB between
cancellation checks. Parsing/serialization also contain bounded synchronous
segments, so this is not a certified wall-clock cancellation deadline.

Integer metadata in the signed/unsigned 64-bit domain remains exact. Other
numeric tokens must survive precise double parsing and decimal serialization
without changing their decimal value; unsupported over-precise, overflow or
underflow values are rejected rather than silently changed. Store larger exact
identifiers/decimal values in strings. `-0` may normalize to `0`; exponent and
whitespace spelling are not preserved. Object ordering is not semantic.

The implementation uses the existing zlib, GLib and Boost installation. JSON is
compiled from Boost headers in one translation unit, without a new runtime DLL.
The required Boost minimum is now 1.83 for precise numeric parsing; the observed
Mac development environment already provides 1.92. No dependency was upgraded
or downloaded by this change. Windows still needs an actual configure/build
against its recorded dependency inventory; this minimum is not Windows evidence.

## Remaining mandatory layers

The UI-independent editable catalog is now implemented as a staging service:
ordered listing, cached Unicode NFC/casefold search over name/tags, add, rename,
tag edits, remove and restore. Duplicate active names receive numbered suffixes;
IDs remain reserved even while an entry is in session trash. Successful edits
increment the revision once, no-ops do not, and overflow/failure/cancellation
does not publish partial state. Metadata edits share immutable artwork buffers.

Snapshots bind the catalog metadata and payloads at one revision. Snapshot
readers pin that state before invoking cancellation callbacks, so closing or
reassigning the snapshot wrapper cannot invalidate an in-progress read. Returned
asset metadata is a value, not a borrowed reference to a discarded snapshot.
Mutations still require the Catalog owner and borrowed inputs to remain alive
and stable through the synchronous operation; UI jobs must retain their service.

Default catalog limits are 32 MiB per artwork, 8 MiB per preview read, 128 MiB of
new artwork buffers, 20,000 retained IDs including trash, and 32 MiB of retained
metadata capacities. Caller-provided spare string/vector capacities are not
retained. Existing package storage, count-bounded map/slot nodes and snapshots
held by callers are separately owned memory, not included in that metadata
counter. Search keys are cached; metadata edits still validate a complete
manifest and are linear in collection size, so they must not be advertised as
constant-time or wired to every UI keystroke without responsiveness testing.

Removal recovery currently lasts only for the session or an explicitly retained
snapshot/prior package. It is **not durable trash**. Closing and reopening would
require the recovery-aware storage service and its still-pending user-facing
recovery workflow; do not treat the in-memory catalog as that writer or expose
unrecoverable deletion as the finished feature.

Before connecting packages to the UI or publishing collections, implement and
test the SVG resource/geometry validation and independent insertion services.
Before rendering untrusted art, reject external entities, scripts and unexpected
file/network access, bound geometry/images, and preserve supported self-contained
definitions, editable data, alpha and color metadata. Do not weaken those
requirements to treat successful package parsing as safe rendering.

The storage service must stage and validate changes, detect external revision
conflicts, retain recoverable previous data, and publish atomically. A catalog
edit must not mutate the active document or its Undo history. These contracts
are not supplied by the ZIP writer. Unknown newer versions require a future
reviewed migration with a recoverable original; version 1 has no migration path.

### Catalog-to-package encoding

`encode_catalog` now emits a deterministic store-only ZIP from one immutable
catalog snapshot. It preserves the snapshot's library/asset identities, revision,
order, metadata and exact artwork bytes. It never increments the revision or
changes the caller's catalog. A callback may close the caller's snapshot or edit
the catalog; the operation still encodes the original revision.

The archive writer checks all declared paths, counts and byte budgets before
invoking any payload reader or allocating the output buffer. It reads one
artwork at a time, verifies its hash, writes CRC-checked entries, and releases
the reader's handle before reading the next entry. Copy/checksum loops check
cancellation every 64 KiB. Existing package storage, overlay buffers and the
final ZIP still remain in memory: this avoids retaining all decoded assets,
but it is not a constant-memory file-streaming writer.

Disposable previews are omitted and must be regenerated by the later preview
service; they are never used to repair damaged artwork. Removed entries are
absent from the emitted catalog. The caller must retain previous committed data
for durable recovery before using this output to replace a collection.

Encoding verifies container structure and artwork integrity only. It does not
certify SVG safety/fidelity, read or write files, perform conflict detection,
recover interrupted writes, or authorize publication. The remaining storage and
document-validation requirements above are unchanged.

### Native storage implementation and remaining qualification

`load_library` now reads bounded native files and verifies artwork integrity.
`save_library` uses an exclusive cooperative lock, same-directory staged package,
validated prior-version recovery copy, conflict checks and native replacement
without a copy fallback. It requires a trusted stable parent and native file
identities. Mounted network shares and removable/non-NTFS filesystems are now
supported through their actual exclusive-create, flush and rename operations,
not a filesystem-name allowlist. A result distinguishes unpublished, unchanged, published and
uncertain states. Callers must not retry a published/uncertain operation blindly.

After each conclusively published save, the panel keeps the five newest
prior-version copies (`.valib-recovery-<library>-r<revision>-…valib`) of that
library in its folder and deletes older ones, each only after it verifies as
exactly that library, revision and hash and is unchanged. `save_library` itself
never deletes files. Copies are grouped per library ID per folder, so a Save As
copy in the same folder shares the window. Trash and staged copies are never
removed automatically.

A writer lock records diagnostic host, process and UTC lines; ownership is
still proven only by its nonce and file identity. A held lock is never taken
over automatically. **Recovery → Remove stale lock…** shows the lock's holder
and age and removes it only on confirmation, and only if it is still exactly
the lock that was shown.

Windows library I/O uses explicit extended-length UTF-16 drive/UNC paths without
requiring a registry change. Import sniffing, SVG import/export, package save/load,
recovery discovery and remembered library paths use the same path handling.
See [network/removable storage and long-path validation](LIBRARY_STORAGE_PATHS_2026-09-07.md)
for the current implementation, tested destinations and remaining limitations.

The initial storage milestone executed 25 macOS cases on internal and external APFS.
These are the same 25 cases on two volumes, not 50 distinct scenarios. The
combined pure-layer UBSan run executes 101 distinct cases. Actual disposable-
volume interruption/full-disk/read-only checks remain unexecuted because macOS
denied the test-image attachment. Later Windows/SMB/exFAT qualification is recorded
in the linked update; physically disconnected-NAS behavior remains unqualified.
Neither successful flush calls nor injected failure tests establish
power-loss durability. Storage integrity also does not certify safe SVG content.

The native view now has development entry points beside Symbols through the
Object menu and dock dialog registry. Registration follows the tested SVG
admission/insertion and retained-controller ownership foundation; it does not
complete storage, recovery, UI or platform acceptance. Existing Symbols behavior
is not replaced. Session slot hints retain collection identity through panel
reopening/moves; they do not themselves reload files after an application restart.
See the dated completion ledger for source-bound tests and remaining gaps.

### Explicit recovery discovery (development implementation)

The panel's collection menu has a compact **Recovery** submenu. Use **Find
recovery copies…**, choose the folder containing the collection's retained
files, then **Review recovery results…**. **Open recovery file…** remains
available when the exact file is known. Folder selection is remembered separately
from Open/Import/Save As; it does not start an automatic scan on launch.

Trash copies (`<library>.trash-<uuid>.valib`) contain only the artwork that was
in session trash when they were written, not the whole collection. A save writes
a new trash copy only when session trash holds artwork not already written to a
trash copy in this session. Trash contents are not admitted when written; they
are admitted when opened or recovered, like any other package.

Discovery is read-only, nonrecursive and runs on the workspace worker. It checks
the writer's staged, prior-version and trash filename families; it ignores
ordinary collections and locks, and never follows candidate symlinks. Limits
are 4096 directory entries, 128 candidate files, 512 MiB encoded package bytes
and 1 GiB aggregate declared expanded bytes. Expanded bytes are reserved before
manifest inflation, including malformed manifests. A limit produces an explicit
incomplete-results warning, not a claim that all copies were inspected. These
are bounded-work limits, not disconnected-filesystem time guarantees.

The results dialog lists verified candidates first and keeps damaged candidates
visible with diagnostics but without an enabled recovery action. A verified
package is not yet approved SVG content. Accepting a copy rechecks its exact
file version and admits all artwork before publishing a new independent,
unsaved collection. It preserves valid names and optional metadata, assigns a
new UUID/revision, and never overwrites or deletes the source. Cancellation,
changed files and rejected artwork leave the active document and library intact.

Native dialog and storage regression tests cover this explicit flow; they do
not qualify physical OS-picker interaction, recovery across application restarts,
large-library performance, power-loss durability, NAS or Windows. Automatic
startup scans are not required by V1; explicit discovery still needs the restart
and interrupted-save acceptance checks in the roadmap. The previously
recorded GTK lifecycle incidents and broader LIB-001 acceptance remain open.

## Evidence

### SVG admission and editable LightBurn conversion checkpoint

The integrated SVG admission service returns an immutable `ValidatedSvg` bound
to the exact copied bytes, asset ID/hash and verified physical root viewport.
It checks namespace-aware XML, local reference graphs, geometry/image budgets,
nested viewports, gradients, inline paint semantics and a subset of native
filters. It preserves admitted XML rather than flattening or stripping content.
The factory's nested SVG/namedview scaffold now passes actual
`stage_selection -> preflight -> native reopen` tests.

Policy 3 additionally admits bounded native tone-v1 metadata, multiline/legacy
flow text, paragraph and generated-frame metadata, relative text metrics and
native text styles. The focused text-context checkpoint passes 95 pure and
18 native cases, including legacy-flow ownership, contextual whitespace,
exclusion-induced glyph movement and viewport-relative inline-size. The original
mixed text/pattern regression is repaired without changing its compatibility
fixture. A further nested text-transform envelope finding remains open; these
passes do not qualify arbitrary SVG or close the renderer/insertion work.
This supersedes the earlier policy-2 compatibility scope, not its remaining
renderer/insertion limitations. Full evidence and failed attempts are retained
in `COMPLETION_WAVE_2026-09-05.md`.

Bitmap staging encodes the current native pixels using the metadata-aware PNG
encoder. It preserves native pixel appearance, alpha and supported ICC/density
metadata, not necessarily the original compressed PNG bytes or pre-Cairo
straight-alpha channel values. Tone parameters stay editable and are not baked
into that PNG; tests compare adjusted and unadjusted staging and subsequent edits.

This is not complete arbitrary-SVG compatibility or an allocator sandbox.
Unsupported stylesheets, procedural effects, non-PNG images and other unhandled
constructs still refuse admission. Native filter intermediates require their
own bounded rendering policy; output-surface dimensions alone do not prove
bounded allocation. Destination CSS isolation, native insertion/Undo and
thumbnail scheduling remain separate unfinished layers.

`artwork-library-lightburn` now converts the observed version-1 Group/Path/Rect
XML into editable SVG using native 2Geom primitives. Explicit millimeter
width/height match the numerical viewBox; root signs are
`(MirrorX ? -1 : 1, MirrorY ? 1 : -1)`, applied after local/parent transforms.
Returned viewport dimensions are rechecked by SVG admission. Raw library extent
fields and preview DPI are not used to establish that scale.

Directed indexed paths preserve closing cubics, separate runs and relative
winding. Source cut/print styling is not reconstructed: neutral unfilled black
outlines are an explicit display policy. Recognized laser-tab pairs are retained
as structured unapplied-tab diagnostics, not applied as guessed gaps. Incomplete
required curve controls refuse the entire entry instead of substituting lines.
The API retains its provisional Draft type names pending complete qualification.

The current local read-only private pipeline test confirms 36 of the 37
entries of a private real-world library convert and pass SVG preflight; one-based entry 19 remains Unsupported
because two required control ordinates are ambiguous. Six entries retain 13
tab-bearing shapes and 34 numeric pairs. The source SHA-256 is checked before
and after. No customer geometry is written to artifacts or published.
This is conversion/admission evidence, not visual fidelity or successful canvas
insertion of those 36 entries. A native LightBurn reference export remains needed
for entry 19; user-approved partial import still requires visible results.

The combined Mac library run executes 232 passing cases across twelve targets,
with GTK enabled and zero skips/failures. The separate private pipeline case is
compiled only with `VACARDS_PRIVATE_LBART_TEST`; it is not a silently skipped
ordinary test. Source/binary identities and retained logs are recorded in the
completion ledger. Windows, native insertion and the full library workflow are
not qualified by these results.

### Native insertion checkpoint (2026-09-05; full UI still incomplete)

The newer focused native insertion suite passes 52 cases with exact payload,
multi-zoom rendering, physical viewport sizing, independent ID/reference, and
one-step Undo/Redo checks. Native preflight passes 21 cases and pure admission
passes 101. This supersedes the earlier statement that native insertion had no
qualification, but does not qualify all private artwork or the whole library.
The original fully overset frame layouts remain explicit non-mutating refusal
cases alongside measured fitting positive round trips.

The controller/thumbnail workflow is still unintegrated. Callback lifetime,
page re-admission, selection-policy restoration, application close/quit and
aggregate memory limits remain required. Source review also found additional
neutral-text editing gaps and a live nested-SVG-transform bounds compatibility
case outside the currently passing insertion corpus. These are tracked in
COMPLETION_WAVE_2026-09-05.md and are not waived by passing focused tests.
No full LIB-001, release, Windows or physical GUI qualification is claimed.

### Observed LightBurn library reader

`LbartArchive` implements read-only indexing and decompression for the fixed-record
variant observed in a real-world LightBurn library. This is **not yet an editable
LightBurn-to-SVG converter**, a PNG decoder, or support for every `.lbart` version.
No Qt dependency or arbitrary signature scanning is used.

The observed layout is big-endian:

| Location | Stored field |
| --- | --- |
| File offset 0 | 32-bit directory offset |
| File offset 4 | 32-bit entry count |
| Directory + entry × 136, bytes 0–103 | 52 UTF-16BE code units, zero-padded name |
| Record + 104, +108 | 32-bit preview offset and encoded byte length |
| Record + 112, +116 | 32-bit artwork-stream offset and encoded byte length |
| Record + 120, +128 | Two big-endian IEEE-754 doubles; raw extent metadata |
| Artwork-stream first 4 bytes | Big-endian declared uncompressed XML byte length |
| Remaining artwork-stream bytes | One zlib stream, including its checksum |

The reader requires the directory to end exactly at EOF and every record's
preview/artwork pair to cover the payload area contiguously from offset 8 to the
directory. Aliases, overlaps, gaps, trailing data, invalid UTF-16/padding,
non-finite/non-positive extent metadata and byte/count budget violations refuse
admission. This strict observed-variant contract must not be advertised as a
complete specification of undocumented future/other LightBurn formats.

Defaults: 512 MiB input, 10,000 entries, 32 MiB decoded artwork per entry, 1 GiB
aggregate declared artwork, and 8 MiB encoded preview per entry. Inflation is
lazy, checks cancellation between 64 KiB output chunks, requires exact decoded
length and checksum/stream termination, and rejects trailing compressed data.
Output offsets use independent `size_t` accounting rather than zlib's platform-
dependent `uLong` totals. Read callbacks may close the archive owner: the active
read retains its immutable storage and a value copy of its record first.

Returned XML and preview bytes remain untrusted. Preview bytes are not decoded
or certified by this layer and never substitute for geometry. Raw extent doubles
are not treated as millimeters: unit/transform/mirroring qualification belongs
to the pending converter. Per-entry XML conversion, metadata mapping, physical
and visual comparison against LightBurn, preview decoding and GUI import remain
required before claiming usable `.lbart` import.

The private extraction test is compiled only with `VACARDS_PRIVATE_LBART_TEST`
and requires explicit `VACARDS_PRIVATE_LBART_SAMPLE`. The ordinary critical test
target contains only synthetic tests; absence of a private customer file does
not produce a skipped mandatory test. The original customer file stays outside
the repository and is never modified or published.

The archive, manifest and package GTest sources are registered in both the test
inventory and the critical build-target list. Standalone UBSan evidence is
recorded in `COMPLETION_WAVE_2026-09-05.md`; full-application, UI, packaging and
Windows results must be recorded separately. Customer `.lbart` content is not
part of the committed synthetic test corpus.
